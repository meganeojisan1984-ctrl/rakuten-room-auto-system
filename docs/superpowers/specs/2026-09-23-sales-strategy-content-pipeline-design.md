# 商品別販売戦略パイプライン設計

日付: 2026-09-23
ステータス: 承認済み設計・実装前

## 目的

楽天ROOMとInstagramの投稿を、商品情報の羅列ではなく、商品ごとの販売戦略に基づいて生成する。商品を把握し、誰のどの悩みを解決する商品かを分析したうえで、紹介文・画像・画像内コメントを一貫して作成する。

## 成功条件

- 商品ごとに「誰へ」「どんな悩みを」「何で解決し」「なぜ今買うか」が定義される。
- 女性向け5カテゴリと男性向け3カテゴリの視点が、商品戦略ブリーフに反映される。
- ROOM本文、Instagram本文、カルーセル、AI画像プロンプト、画像内コメントが同じ戦略ブリーフを参照する。
- 投稿素材の基本順序が「悩み提示 → ニーズへの共感 → 商品による解決 → 価格・レビュー等の根拠 → 楽天ROOM購入導線」になる。
- API失敗時も投稿全体は停止せず、商品情報から作る安全なフォールバックブリーフで継続する。
- 根拠のない使用体験、効果保証、レビュー内容の創作をしない。

## 戦略ブリーフ

既存の `ProductContentBrief` を販売戦略の共有オブジェクトへ拡張する。最低限、次の情報を保持する。

- 商品把握: 商品名、価格、レビュー、商品説明から抽出した特徴、季節性、クーポン・ポイント
- ターゲット: audience、性別視点、想定利用者、利用シーン
- ニーズ分析: 購入前の悩み、購入動機、選定基準
- 解決設計: 商品情報に基づく解決策、訴求軸、根拠情報
- 表現設計: Instagram本文構成、画像シーン、色・雰囲気、画像内コメント
- 購入導線: CTA、ROOMへ誘導する理由、必要な注意書き

## APIとフォールバック

既存のOpenAIテキストクライアントを使い、1商品につき販売戦略ブリーフを1回生成する。JSON相当の構造化出力を要求し、必須項目の検証に失敗した場合は採用しない。

生成失敗、空応答、構造不正の場合は、既存の決定論的な商品情報抽出ロジックから安全なブリーフを作る。フォールバックでは効果保証や実体験を補わず、商品説明・価格・レビューなど確認できた情報だけを使用する。

## データフロー

```text
商品取得
  ↓
商品把握・販売戦略API
  ↓
販売戦略ブリーフ（1商品につき1つ）
  ├─ ROOM紹介文
  ├─ Instagram紹介文
  ├─ カルーセル5枚
  ├─ AI背景画像プロンプト
  └─ 画像内コメント・購入CTA
```

mainとauto-postの両方で同じブリーフ生成経路を使う。Instagram側で再生成せず、投稿処理へブリーフを渡して同一内容を再利用する。

## 視点ルール

- 女性向け: 美容・見た目・続けやすさ・日常のケア・生活への取り入れやすさ
- 男性向け: 機能・効率・接続性・耐久性・仕事や趣味での用途
- 商品カテゴリが視点にそぐわない場合でも、根拠のない性別ステレオタイプを追加せず、カテゴリと商品説明を優先する。

## エラー処理

- 販売戦略APIの失敗はフォールバックへ切り替え、投稿処理を継続する。
- 必須項目不足のブリーフは下流へ渡さない。
- Instagram画像生成の失敗は既存の通知・投稿失敗処理を維持する。
- APIキーや商品情報などの秘密値はログへ出力しない。

## テスト方針

- 戦略APIプロンプトが商品情報、カテゴリ、persona、要求スキーマを含むこと。
- 正常なAPI応答が構造化ブリーフへ変換されること。
- 不正応答・APIエラーが決定論的フォールバックへ切り替わること。
- 女性／男性のニーズ分析・訴求軸・画像シーンが分かれること。
- 全下流素材が同じブリーフの特徴・CTAを参照すること。
- 悩み、解決、根拠、購入導線の順序を検証すること。
